## Normal operation

An authenticated message to `annals@stammtischbrewery.com` enters the existing dedicated Gmail and owner-only Drive/Apps Script intake; eligible signed material is processed under **recorded scoped standing permissions**, not a fresh owner approval. Screening must preserve actual speaker attribution, member recipe quantities and syrup steps, source photography and withdrawal/revocation checks. A held image does **not** hold otherwise safe eligible text. Confirm published state only from signed repository data **and the actual live Pages derivative**; a dispatch acceptance alone is not live success.

The original restricted `/exec` deployment was last privately verified at **Version 59** (23 October), with exactly **one five-minute `runAnnalsProductionIntake` trigger**. Do not rerun the cadence helper, recreate the project or disturb saved member grants, cursors, signing keys and replay evidence. Existing publisher workflows request Pages deployment. The earlier natural member-email publication witness is recorded in [current state](current-state.md); it is one sample, not a latency guarantee.

For an ordinary website edit: commit reviewed source to `main`, run affected checks, let Pages deploy and verify the affected public URL. **Do not enter Apps Script or perform a signing/consent exercise for copy/layout.**

## Private source and credential changes

**Open-contribution activation:** [#303](https://github.com/justinpfisher/Stammtisch/pull/303) is merged and tested but not privately installed. Once the owner project is accessible, update **both** `AutoCore.gs` (from `scripts/annals/AutoCore.js`) and `Production.gs`, read back both saved files and the unchanged five-minute trigger, advance that same `/exec`, and verify an eligible external text contribution through the existing signed writer and public Pages. Only then change the public Annals invitation from “Members only” to open contributions. No new registration, secret or scheduled job is needed.

When a genuine private-code change is necessary:
1. Compare only changed modules with the reviewed `main` baseline; if there is evidence of an incident/drift, expand the comparison. Use `scripts/annals/build-install-package.py` to prepare owner-private reviewed code, never a public kit with private settings.
2. In the **same original owner-only Apps Script project**, save the affected modules and dependencies in a safe order, read back exact saved source, then advance the **existing** `/exec` deployment in place. Saving HEAD affects its trigger immediately; it does not update a versioned `/exec`.
3. Verify only the affected non-secret settings/behaviour and exactly one owner-run intake trigger. Preserve manifest/scopes, consent, Drive folders, publication receipts, permanent historical signing keys, cursors, attempts and replay/withdrawal records. Do not reset and redispatch an uncertain request.
4. If credential access is inadequate, use one authenticated owner repair; no broad key rotation, new Apps Script project or permission expansion without a real need.

The private `ANNALS_GITHUB_TOKEN_EXPIRES_AT` must reflect the token **actually installed**, not a guessed lifetime. The installed value and authenticated provider metadata both showed **16 January 2027, 00:00 UTC**, with repository-only scope. The November source fallback is not the effective cutoff. Do not rotate now. Renew in place before that verified actual stop or migrate to a supported GitHub App with only required repository dispatch permission, preserving issuance and replay safeguards. Never disable the stop merely to hide the outage risk. Read-only owner diagnostics may confirm configuration without printing token values.

A clear authenticated member decision needs no second Club adoption. Publish ordinary settled public wording with focused checks. ## Cocktail images and other photographs

Eligible input formats are JPEG, PNG, WebP, HEIC and HEIF; real private acceptance for the latter four has not yet been demonstrated. Apply the existing installed conversion/screening safeguards and source rights before public output, strip metadata and preserve orientation. Publish a screened authentic original rather than a fabricated photographic edit if the optional transformation fails.

**The US$2/photo reservation rule is retired.** The already owner-verified provider project-enforced **US$5/month hard cap** is the monetary boundary. The #247 source was installed and read back in Version 58, preserving historical private reservations. A paid operation needs an eligible source-bound signed permission, an existing restricted image credential and verified cap, and one exclusive durable attempt marker in the canonical private output directory. The private issuer now uses `annalsCocktailEditorialPermitInEditor(itemId,photoIndex)` without a monetary reservation. The runner takes `--entry`, `--reference` (Kingston), `--permit`, `--private-output`, and `--execute` (or optional `--check-handoff` without billing); set `ANNALS_EDITORIAL_PRIVATE_DIR` to the existing protected output directory, or reuse its historical `ANNALS_EDITORIAL_BUDGET_DIR` setting as a compatibility alias. **Do not repeat a potentially billed operation automatically.** Preserve pre-existing issuer receipts and historical source attempts as replay evidence. Source rights, full-resolution visual fidelity, model entitlement and the first actual Kingston edit remain unverified. A failed optional edit never holds eligible original photography or text.

## Incident rule

Hold only the affected action for absent individual rights, invalid private authentication, genuine source conflict, unknown billable result, or independently unverified death. Continue unrelated authorised publication. Log one actionable exception privately and, when safe, a metadata-only checkpoint in Issue #24. Dated private runbooks remain in Git history; do not resurrect retired acceptance gates.
