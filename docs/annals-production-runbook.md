## Operating contract

1. Accept only the six specific contributor addresses previously confirmed by the owner, stored **only** in production Script Property `ANNALS_ALLOWED_SENDERS`. Verify exactly six distinct mailboxes privately; never put the list, authentication records, raw mail or user contacts in public GitHub files, issues, PRs, Actions logs or builds. A `From:` match is insufficient: preserve the existing single Google `Authentication-Results` aligned DKIM/DMARC validation; hold ambiguous or unverifiable forwarded mail.
2. A participating member must have affirmative, revocable **private AI processing** consent and a separately scoped standing consent for **automatic public text and screened images**, registered privately and evidenced as the person's own choice. The current system supports one-time authenticated code challenges, including a combined text-and-safe-image standing permission; existing private records may be reused where scope genuinely covers the requested use. An owner attestation is recorded separately from authenticated replies and cannot be forged into one. The invitation plainly explains public GitHub history, potential persistence after withdrawal, conspicuous censorship, anonymous credit, ownership and third-party limitations. An owner invitation is **not** a member’s consent. Members may revoke either permission by authenticated exact-command email or the owner-only desk. Revocation prevents new automatic publication; it does not erase existing public history.
3. The system records consent privately at receipt and checks both live consents again before publication. It cannot retrospectively publish emails received before affirmative publication consent. The AI model categorises and extracts details into a **private draft**; it has no tools, cannot grant permission, and is constrained to a pinned model, structured output and the existing application budget.
4. `AutoCore.js` is a narrow deterministic eligibility filter. It publishes only a verified, allowed category unless a **material** unresolved AI flag concerns privacy, ownership, speaker permission, accurate recipe transcription or security. Generic editorial uncertainty does not block publication, and an unsupported AI headline falls back to the actual subject. Self-authored quotations introduced explicitly as “my quote” or “I said” may publish under the contributor's standing consent; third-party quotations are held. The public summary uses the contributor's actual wording. For cocktail recipes, recorded ingredient and method lines retain the author's actual words and original measurements. Missing instructions or amounts can be supplemented with **clearly marked suggested preparation / quantities** in a separate editorial section. Those approximations are neither historical evidence nor replacements for recorded syrup quantities; ambiguous source measurements are not silently presented as verified. Unrelated banter and editorial commentary need not appear inside the recipe. Text is publicly attributed `anonymous` unless a separate manual exception and attribution consent exists. The public `Submitted YYYY-MM` label is the receipt period, **not a fabricated event date**. No AI paraphrase or unconfirmed date is silently presented as a club fact.
5. Strong profanity receives visible `[EXPLETIVE]` substitutions; `[POOP]` is used for the occasional taste/smell expression. Mild words such as “damn” and “hell” remain. Originals stay private. The public renderer refuses unredacted strong profanity, including on the manual path. Any censored direct quotation must visibly say it is **not verbatim**, retain the uncensored source privately, and have the actual speaker’s public-use permission. Self-authored quotations with the member’s standing consent can publish; other-person quotations without their permission, identifying anecdotes, allegations, uncertain historical attribution, ambiguous recipes and other material unresolved concerns are **held privately**, not rewritten into a different story.
6. Suitable photographs **can publish automatically** after the contributor's scoped standing permission and a positive private AI image-safety check. The current bounded first release supports one JPEG/PNG/WEBP/HEIC/HEIF source image per submission if the existing Drive service can provide a small baseline JPEG thumbnail; it strips image metadata, checks dimensions/structure and signs **only that derivative** (up to 32 KiB) for GitHub. A small, isolated non-identifying cocktail or club object is eligible; identifying people, guests, interiors, reflections, readable private details, failed conversion, unsupported PDFs, multiple images and uncertain rights are held privately for exception handling. The original stays private. A safe independent text entry may still publish if the photo is held. The registered owner attestation does not make AI identification or photo screening infallible. Google Drive's thumbnail method can return null; no alternative paid image processor or public-original fallback is allowed.
7. Only the exact eligible entry is signed in private. Automatic entries use the distinct `annals-auto-entry` repository dispatch with separate domain-tagged `standing-consent-text-v1` and `standing-consent-image-v1` HMAC modes. The image mode binds the exact small metadata-stripped JPEG digest, alternative text and separate contributor photo permission to the signed entry. GitHub checks the signature, exact public fields, category, no-photo rule, replay and duplicate protection before committing to `main`. The separate manual signature path, owner-only corrections and withdrawals remain. No private evidence or source message crosses into public GitHub. The site creates only populated categories; no pending or empty category appears.
8. Dispatch HTTP 204 means only **accepted for processing**, never “published”. The private reconciliation step must observe the matching signed entry/digest in the public archive **and** its entry ID on live GitHub Pages before recording `verified_live` and attempting a one-time contributor notification. Failed/unknown deliveries, interrupted provider attempts, consent ambiguity and failed publication are held. **Never automatically re-dispatch an uncertain attempt.** If a signed dispatch is still unverified after 24 hours, the private owner receives one status notice; this is not a claim of public success and does not cause a duplicate dispatch.
9. Submissions about celebrity deaths must never change Celebration of Life scores, register, death verification or OneSignal alerts. No new app, account, paid subscription, runner or public self-hosting is required.

## Supported unattended content and held exceptions

| Contribution | Automatic handling |
| --- | --- |
| Original cocktail recipe with verified recorded values but incomplete preparation or some missing quantities | **Eligible** after the relevant contributor consent and checks, with original facts preserved and all AI-generated quantities/steps visibly marked as editorial suggestions |
| Short, non-identifying Assembly/monthly note, club history or artefact description with literal source wording and no uncertainty | **Potentially eligible**, subject to the same conservative checks |
| Strong but non-sensitive profanity in otherwise eligible text | **Eligible after visible censorship** and the permanent editorial notice |
| Self-authored, accurately transcribed quotes explicitly introduced as “my quote” or “I said” | **Eligible**, with standing consent; visible non-verbatim label when censored |
| Third-party quotations, uncertain handwriting/recipes, allegations, identity- or location-bearing stories | **Held privately** |
| A single non-identifying drink/artefact image from a contributor whose standing image permission is recorded, positively screened and converted to a small metadata-free derivative | **Eligible for automatic signed publication**; source original stays private |
| Identifying people, guests, private interiors, image-based allegations, multiple-image submissions, failed/oversized thumbnails or unverified permissions | **Held privately**; independent safe text may publish |
| HEIC/HEIF/WEBP whose existing private Drive thumbnail becomes a suitable safe JPEG | **Potentially eligible**; if conversion/screening fails, hold privately |
| PDF, oversized or unsupported image conversion, ambiguous personal details | **Held privately**, with originals retained in approved private storage/Gmail |
| Any contributor without both active individual consents; prior-to-consent submissions; failed or ambiguous sender authentication | **Never automatically published** |
