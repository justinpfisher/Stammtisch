## Operating contract

1. Accept only the six specific contributor addresses previously confirmed by the owner, stored **only** in production Script Property `ANNALS_ALLOWED_SENDERS`. Verify exactly six distinct mailboxes privately; never put the list, authentication records, raw mail or user contacts in public GitHub files, issues, PRs, Actions logs or builds. A `From:` match is insufficient: preserve the existing single Google `Authentication-Results` aligned DKIM/DMARC validation; hold ambiguous or unverifiable forwarded mail.
2. A participating member first explicitly accepts **private AI processing** through the existing one-time code challenge. Separately, they must personally accept **standing automatic public text publication** through a distinct, authenticated one-time code challenge. The invitation plainly explains public GitHub history, potential persistence after withdrawal, conspicuous censorship, anonymous credit, ownership and third-party limitations. An owner invitation is **not** a member’s consent. Members may revoke either permission by authenticated exact-command email or the owner-only desk. Revocation prevents new automatic publication; it does not erase existing public history.
3. The system records consent privately at receipt and checks both live consents again before publication. It cannot retrospectively publish emails received before affirmative publication consent. The AI model categorises and extracts details into a **private draft**; it has no tools, cannot grant permission, and is constrained to a pinned model, structured output and the existing application budget.
4. `AutoCore.js` is a narrow deterministic eligibility filter. It publishes only a verified, allowed category unless a **material** unresolved AI flag concerns privacy, ownership, speaker permission, accurate recipe transcription or security. Generic editorial uncertainty does not block publication, and an unsupported AI headline falls back to the actual subject. Self-authored quotations introduced explicitly as “my quote” or “I said” may publish under the contributor's standing consent; third-party quotations are held. The public summary uses the contributor's actual wording. For cocktail recipes, extracted ingredient lines and method steps must match the original literally, with no omitted measurement, quantity, unit or method. Unrelated banter and editorial commentary need not appear inside the recipe. Text is publicly attributed `anonymous` unless a separate manual exception and attribution consent exists. The public `Submitted YYYY-MM` label is the receipt period, **not a fabricated event date**. No AI paraphrase or unconfirmed date is silently presented as a club fact.
5. Strong profanity receives visible `[EXPLETIVE]` substitutions; `[POOP]` is used for the occasional taste/smell expression. Mild words such as “damn” and “hell” remain. Originals stay private. The public renderer refuses unredacted strong profanity, including on the manual path. A manually approved censored quotation must visibly say it is **not verbatim**, retain the uncensored source privately, and have the actual speaker’s public-use permission. Ordinary quotation, identifying anecdote, allegation, historical attribution, ambiguous recipe and other unresolved material is **held privately**, not rewritten into an alternative story.
6. Pictures are not eligible for unattended publication yet. Image rights, face/reflection/context safety and metadata removal cannot be proved automatically from the existing source. JPEG/PNG originals may remain privately staged; a **self-contained, safe text component** may publish separately where it does not rely on the attachment. HEIC/PDF and disputed or risky images stay held. The existing separately consented, manually reviewed JPEG derivative pathway remains available.
7. Only the exact eligible entry is signed in private. Automatic entries use the distinct `annals-auto-entry` repository dispatch and domain-tagged `standing-consent-text-v1` HMAC approval. GitHub checks the signature, exact public fields, category, no-photo rule, replay and duplicate protection before committing to `main`. The separate manual signature path, owner-only corrections and withdrawals remain. No private evidence or source message crosses into public GitHub. The site creates only populated categories; no pending or empty category appears.
8. Dispatch HTTP 204 means only **accepted for processing**, never “published”. The private reconciliation step must observe the matching signed entry/digest in the public archive **and** its entry ID on live GitHub Pages before recording `verified_live` and attempting a one-time contributor notification. Failed/unknown deliveries, interrupted provider attempts, consent ambiguity and failed publication are held. **Never automatically re-dispatch an uncertain attempt.**
9. Submissions about celebrity deaths must never change Celebration of Life scores, register, death verification or OneSignal alerts. No new app, account, paid subscription, runner or public self-hosting is required.

## Supported unattended content and held exceptions

| Contribution | Automatic handling |
| --- | --- |
| Short, original, self-contained cocktail recipe with every ingredient, fraction, unit and step faithfully matched to the submitted text and no unresolved flags | **Eligible** after both consents, genuine sender authentication and private policy checks |
| Short, non-identifying Assembly/monthly note, club history or artefact description with literal source wording and no uncertainty | **Potentially eligible**, subject to the same conservative checks |
| Strong but non-sensitive profanity in otherwise eligible text | **Eligible after visible censorship** and the permanent editorial notice |
| Self-authored, accurately transcribed quotes explicitly introduced as “my quote” or “I said” | **Eligible**, with standing consent; visible non-verbatim label when censored |
| Third-party quotations, uncertain handwriting/recipes, allegations, identity- or location-bearing stories | **Held privately** |
| A submitted photograph, including an otherwise innocuous cocktail picture | **Held for separate image consent/safety review**; independent, safe text may publish |
| PDF, HEIC, unsupported, oversized or ambiguous material | **Held privately**; originals remain in approved private storage/Gmail |
| Any contributor without both active individual consents; prior-to-consent submissions; failed or ambiguous sender authentication | **Never automatically published** |
